# 가족 구성원 관리

## 사용자 목표

관리자는 우리 가족만 접근할 수 있는 가정 공간을 만들고 가족 구성원의 가입, 승인, 권한과 탈퇴 상태를 관리한다.

초기 관리자는 서비스 소유자인 남편이며, 최초 구성원은 관리자와 관리자가 초대한 아내 계정이다.

## 용어

- `가정(household)`: 일정, 가계부, 디데이와 목표를 공유하는 최상위 데이터 공간
- `관리자(admin)`: 가족 구성원과 가입 요청을 관리할 수 있는 사용자
- `구성원(member)`: 관리자가 승인하여 가정 공간을 이용하는 사용자
- `초대(invitation)`: 관리자가 특정 개인 이메일 주소로 1회용 가입 링크를 발송해 가족으로 추가하는 절차
- `가입 요청(join request)`: Google 계정 사용자가 특정 가정에 참여하기 위해 관리자에게 승인을 요청하는 절차
- `탈퇴 처리`: 관리자가 구성원의 가정 접근 권한을 종료하는 절차

## 역할과 권한

### 관리자

관리자만 다음 작업을 할 수 있다.

- 가족 구성원 초대
- 가입 요청 승인 또는 거절
- 구성원 정보와 상태 수정
- 구성원 탈퇴 처리
- 만료되지 않은 초대 취소
- 구성원 목록과 가입 요청 목록 조회

### 구성원

구성원은 다음 작업을 할 수 있다.

- 승인된 가정의 공유 기능 이용
- 자신의 표시 이름과 개인 환경설정 수정
- 자신의 로그인 계정 연결 상태 조회

구성원은 다른 구성원을 초대, 승인, 수정 또는 탈퇴 처리할 수 없다. 구성원의 자발적 가정 탈퇴도 관리자 승인 없이 즉시 처리하지 않는다.

## MVP 포함 범위

- 최초 관리자 계정으로 가정 생성
- 관리자가 아내의 이메일 주소로 초대 생성
- 초대받은 사용자가 본인 계정을 활성화하고 초대를 수락
- 관리자와 승인된 구성원이 하나의 가정 공간 공유
- 관리자 전용 구성원 목록
- 관리자의 구성원 상태 변경과 탈퇴 처리
- 초대 만료와 취소

## 후속 확장 범위

- Google 계정 로그인
- Google 로그인 사용자의 가정 가입 요청
- 관리자에게 가입 요청 표시
- 관리자의 승인 또는 거절
- 승인 전 사용자의 가정 데이터 접근 차단

Google 로그인 도입 후에도 Google 계정 인증 성공이 가족 구성원 승인을 의미하지 않는다. 인증과 가정 가입 승인을 별도 단계로 유지한다.

## 사용자 흐름

### 최초 가정 생성

1. 최초 사용자가 관리자 계정을 생성한다.
2. 시스템이 관리자를 소유자로 하는 가정을 생성한다.
3. 관리자는 가족 구성원 관리 화면으로 이동한다.

### 관리자 이메일 초대 방식

1. 관리자가 가입할 가족 구성원의 개인 이메일 주소를 입력한다.
2. 시스템은 동일 가정의 활성 구성원 또는 유효한 초대인지 중복 확인한다.
3. 시스템은 만료 시간이 있는 1회용 초대를 생성한다.
4. 시스템은 해당 개인 이메일 주소로 가입 경로가 포함된 초대 메일을 발송한다.
5. 초대받은 사용자는 메일의 링크를 열어 해당 이메일 주소를 계정 ID로 가입한다.
6. 시스템은 이메일 소유 확인 후 초대를 수락한다.
7. 시스템은 초대 이메일과 가입 계정 ID가 일치하는지 확인한다.
8. 시스템은 해당 사용자를 `member` 역할의 활성 구성원으로 등록한다.
9. 사용한 초대 링크는 다시 사용할 수 없게 처리한다.

관리자가 다른 사용자의 비밀번호를 직접 만들거나 전달하지 않는다.

초대 메일은 단순 알림이 아니라 가입할 가정과 1회용 초대 토큰이 포함된 가입 경로다. 초대받은 사용자는 일반 가입 화면이 아니라 초대 링크에서 가입을 시작해야 해당 가정과 연결된다.

### Google 계정 가입 요청 방식

1. 사용자가 Google 계정으로 로그인한다.
2. 사용자가 참여할 가정을 선택하거나 관리자가 제공한 가입 식별 정보를 입력한다.
3. 시스템은 `pending` 상태의 가입 요청을 생성한다.
4. 관리자가 요청자의 이름과 Google 계정 이메일을 확인한다.
5. 관리자가 승인하면 사용자를 `member`로 등록한다.
6. 관리자가 거절하면 요청은 `rejected` 상태가 되며 가정 데이터 접근 권한을 부여하지 않는다.

### 구성원 탈퇴 처리

1. 관리자가 구성원 목록에서 탈퇴 처리할 사용자를 선택한다.
2. 시스템은 공유 데이터에 미치는 영향을 안내하고 재확인을 요청한다.
3. 관리자가 확정하면 구성원 상태를 `removed`로 변경한다.
4. 탈퇴 처리된 사용자의 모든 가정 데이터 접근을 즉시 차단한다.
5. 사용자가 과거에 작성한 공유 데이터는 삭제하지 않고 작성자 기록을 유지한다.
6. 탈퇴 처리 사실을 감사 로그에 기록한다.

## 상태 모델

### 가족 구성원 상태

- `active`: 승인되어 가정 데이터에 접근할 수 있음
- `suspended`: 관리자가 일시적으로 접근을 차단함
- `removed`: 가정에서 탈퇴 처리되어 접근할 수 없음

### 초대 상태

- `pending`: 아직 사용되지 않은 유효한 초대
- `accepted`: 정상적으로 수락된 초대
- `expired`: 만료 시간이 지난 초대
- `cancelled`: 관리자가 취소한 초대

### 가입 요청 상태

- `pending`: 관리자 판단 대기
- `approved`: 관리자가 승인함
- `rejected`: 관리자가 거절함
- `cancelled`: 요청이 취소됨

## 데이터 규칙

- 사용자가 로그인 화면에 입력하고 확인하는 계정 ID는 이메일 주소다.
- 이메일 주소는 정규화된 형태로 유일해야 한다.
- DB 관계와 작성자 이력에는 이메일 주소가 아닌 변경 불가능한 내부 `user_id`를 사용한다.
- 한 사용자는 동일 가정에 하나의 활성 구성원 관계만 가질 수 있다.
- 동일 이메일과 가정에 대해 여러 개의 유효한 초대를 만들 수 없다.
- 동일 사용자와 가정에 대해 여러 개의 `pending` 가입 요청을 만들 수 없다.
- 이메일 비교 시 앞뒤 공백을 제거하고 대소문자를 구분하지 않는다.
- 초대 토큰 원문은 DB에 저장하지 않고 해시값만 저장한다.
- 구성원 제거는 hard delete가 아닌 상태 변경으로 처리한다.
- 모든 승인, 거절, 역할 및 상태 변경에는 처리 관리자와 처리 시각을 기록한다.
- 모든 업무 데이터는 `household_id`를 통해 가정 경계 안에 둔다.

## 권한 규칙

- `active` 구성원만 해당 가정의 공유 데이터에 접근할 수 있다.
- `pending`, `suspended`, `removed` 사용자는 공유 데이터에 접근할 수 없다.
- 구성원 관리 mutation은 서버와 DB 정책 모두에서 관리자 여부를 검사한다.
- 프런트엔드에서 관리자 버튼을 숨기는 것만으로 권한을 구현하지 않는다.
- 사용자가 임의의 `household_id`나 구성원 ID를 전송해도 다른 가정의 데이터를 조회하거나 변경할 수 없어야 한다.
- 관리자는 자신이 관리하는 가정의 구성원만 관리할 수 있다.

## 오류 및 예외

- 이미 활성 구성원인 이메일을 다시 초대함
- 동일 이메일에 유효한 초대가 이미 존재함
- 초대가 만료되거나 취소됨
- 초대 이메일과 로그인한 계정 이메일이 다름
- 이미 처리된 가입 요청을 다시 승인 또는 거절함
- 구성원이 관리자 전용 API를 직접 호출함
- 탈퇴 처리된 사용자가 기존 세션으로 접근을 시도함
- 마지막 관리자를 탈퇴 처리하거나 권한 해제하려고 함

마지막 관리자 처리 정책은 확정 전까지 차단하는 것을 기본값으로 한다.

## 감사 로그

다음 작업은 감사 로그에 기록한다.

- 초대 생성, 수락, 취소와 만료
- 가입 요청 생성, 승인과 거절
- 구성원 상태 변경
- 구성원 탈퇴 처리
- 관리자 역할 변경

감사 로그에는 작업 유형, 대상 사용자, 처리 관리자, 가정 ID와 처리 시각을 저장하되 초대 토큰이나 인증 자격 증명은 기록하지 않는다.

## 인수 조건

- 최초 관리자가 아내 이메일로 초대를 생성할 수 있다.
- 초대받지 않았거나 승인되지 않은 사용자는 가정 데이터에 접근할 수 없다.
- 초대받은 사용자는 본인 이메일 인증 후 한 번만 초대를 수락할 수 있다.
- 관리자는 구성원 목록과 상태를 조회하고 탈퇴 처리할 수 있다.
- 일반 구성원은 다른 구성원을 승인, 수정 또는 탈퇴 처리할 수 없다.
- 탈퇴 처리된 사용자의 기존 세션으로도 공유 데이터 접근이 차단된다.
- 다른 가정의 관리자도 이 가정의 구성원을 관리할 수 없다.
- 향후 Google 가입 요청을 추가할 수 있도록 초대와 구성원 관계가 분리되어 있다.

## 필수 테스트

- 최초 가정과 관리자 생성
- 정상 초대와 수락
- 중복 초대 차단
- 만료·취소·재사용 초대 차단
- 초대 이메일 불일치 차단
- 관리자 구성원 상태 변경
- 일반 구성원의 관리자 API 호출 차단
- 다른 가정 구성원 조회·수정 차단
- 탈퇴 처리 직후 접근 차단
- 마지막 관리자 탈퇴 처리 차단
- Google 가입 요청 생성·승인·거절 테스트는 해당 기능 도입 시 추가

## 미결정 사항

- 관리자를 한 명만 둘지 복수 관리자를 허용할지
- 관리자 계정 분실 시 복구 절차
- 구성원의 자발적 탈퇴 요청 기능과 관리자 승인 절차
- 탈퇴 처리된 사용자의 재가입 허용 조건
- Google 가입 요청에서 가정을 찾는 방법: 초대 링크, 가족 코드 또는 관리자 이메일
