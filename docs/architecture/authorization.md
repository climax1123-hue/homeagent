# 인증과 가족 권한 아키텍처

## 권한 경계

`household`를 모든 공유 데이터의 최상위 보안 경계로 사용한다.

```text
인증 사용자
  └─ household_members
       ├─ household_id
       ├─ user_id
       ├─ role: admin | member
       └─ status: active | suspended | removed
```

로그인 세션은 사용자 신원만 증명한다. 실제 업무 데이터 접근은 `household_members`의 역할과 상태를 확인한 뒤 허용한다.

사용자에게 보이는 계정 ID는 이메일 주소지만, 테이블 간 관계와 RLS 판정에는 인증 시스템이 발급한 변경 불가능한 UUID `user_id`를 사용한다. Google 계정은 provider의 고유 ID를 내부 사용자와 연결하며 이메일 주소 자체를 외부 계정의 영구 식별자로 가정하지 않는다.

## 권장 데이터 엔터티

### `households`

- 가정 기본 정보
- 최초 관리자 생성 시 함께 생성

### `household_members`

- 사용자와 가정의 관계
- 역할과 활성 상태
- 제거하더라도 이력 보존

### `household_invitations`

- 관리자가 생성한 이메일 초대
- 토큰 해시, 대상 이메일, 만료 시각과 처리 상태

### `household_join_requests`

- 향후 Google 계정 사용자의 가입 요청
- 요청자, 대상 가정, 상태와 관리자 처리 정보

### `audit_logs`

- 구성원 관리와 가입 승인 관련 중요 변경 기록

## RLS 정책 방향

- `active` 구성원은 자신이 속한 가정의 허용된 업무 데이터를 조회한다.
- `admin + active` 사용자만 구성원과 가입 요청을 변경한다.
- 초대 수락은 서버 함수에서 토큰, 이메일과 상태를 검증한다.
- 승인 대기 사용자는 가정 이름 등 가입 절차에 필요한 최소 정보만 본다.
- `suspended`와 `removed` 사용자는 업무 테이블을 조회하지 못한다.
- service role을 일반 CRUD 우회 수단으로 사용하지 않는다.

## 세션과 권한 변경

관리자가 구성원을 정지하거나 탈퇴 처리하면 다음 API 요청부터 새 상태가 적용되어야 한다. JWT 안의 오래된 역할 정보만 신뢰하지 않고 DB의 현재 구성원 상태를 RLS 또는 서버 함수에서 확인한다.

## 관리자 전용 변경

구성원 승인, 거절, 상태 변경과 탈퇴 처리는 다음 두 계층에서 검증한다.

1. 서버 함수에서 요청자의 인증, 관리자 역할과 입력을 검증한다.
2. PostgreSQL 정책 또는 보안 함수에서 동일 가정 관리자 여부를 다시 검증한다.

UI의 메뉴 노출 여부는 사용 편의를 위한 것이며 보안 경계로 사용하지 않는다.

## 관리자 안전장치

- 마지막 활성 관리자의 탈퇴 또는 권한 해제를 차단한다.
- 자기 자신을 탈퇴 처리하는 기능은 정책 확정 전까지 차단한다.
- 관리자 변경은 감사 로그에 남긴다.
- 복수 관리자 지원 여부는 제품 정책 확정 후 결정한다.
