# statement-import - Plan Document

> Version: 1.0.0 | Date: 2026-08-28 | Status: Approved
> Level: Dynamic

## 1. 개요

### 1.1 목적

은행·카드사 웹사이트에서 내려받은 거래 명세 파일을 가족 또는 개인 장부에 업로드하고, 열 매핑과 거래 검토를 거쳐 가계부 원장에 안전하게 일괄 반영한다.

### 1.2 기본 원칙

- 원본 금융 파일을 Git이나 공개 저장소에 저장하지 않는다.
- 가능한 파싱은 브라우저에서 수행하고, 원본 파일은 기본적으로 영구 보관하지 않는다.
- 자동 판단 결과를 바로 원장에 넣지 않고 사용자가 검토·확정한다.
- 같은 파일이나 같은 거래를 반복 업로드해도 중복 입력을 방지한다.
- 모든 import 데이터는 `household_id`, `book_id`, 업로드 사용자 권한을 따른다.

## 2. 목표

- [ ] CSV와 XLSX 파일을 업로드한다.
- [ ] 다양한 은행/카드사 열 이름과 날짜·금액 형식을 인식한다.
- [ ] 사용자가 거래일, 적요, 출금, 입금, 금액 열을 직접 매핑할 수 있다.
- [ ] 파싱 오류 행과 정상 행을 구분해 표시한다.
- [ ] 결제수단과 기본 카테고리를 선택한 뒤 거래별 내용을 수정한다.
- [ ] 파일 내부 중복과 기존 원장 중복 후보를 표시한다.
- [ ] 선택한 행만 한 번의 확정 작업으로 원장에 반영한다.
- [ ] 업로드 결과와 실패 사유를 요약한다.

## 3. 범위

### 3.1 포함

#### 파일 입력

- `.csv`, `.xlsx` 지원
- 최대 파일 크기 10MB, 최대 10,000행
- CSV 문자 인코딩 UTF-8, UTF-8 BOM, CP949/EUC-KR 후보 처리
- XLSX 첫 번째 또는 사용자가 선택한 sheet 읽기
- 암호화 파일, 매크로 파일, 수식 실행 거부

#### 열 매핑

- 필수: 거래일, 거래 방향/출금·입금 또는 부호 있는 금액
- 선택: 거래시간, 거래처/적요, 메모, 잔액
- 은행별 헤더 preset을 추가할 수 있는 adapter 구조
- 자동 매핑 결과를 사용자가 수정하고 미리보기

#### 정규화

- 거래일을 `YYYY-MM-DD`로 변환
- 금액에서 쉼표·통화기호를 제거하고 양의 `bigint` 문자열로 변환
- 출금은 expense, 입금은 income으로 변환
- 거래처와 메모의 공백·제어문자 정리
- 원본 행 번호와 파싱 오류 유지

#### 검토와 반영

- 대상 장부와 결제수단 선택
- 행별 포함/제외, 유형·금액·일자·거래처·카테고리 수정
- 동일 파일 fingerprint와 정규화 거래 fingerprint를 이용한 중복 표시
- confirmed 행만 원장 transaction으로 원자적 반영
- import batch 단위 처리 결과와 생성 transaction 연결

### 3.2 제외

- 은행 Open API 실시간 연결
- PDF 명세와 이미지 OCR
- 암호가 설정된 Excel 파일
- AI/ML 기반 자동 분류
- 사용자의 수정 결과 학습
- 원본 금융 파일 장기 보관

## 4. 사용자 흐름

```text
가계부 → 명세 가져오기
→ 대상 장부 선택
→ CSV/XLSX 파일 선택
→ sheet/인코딩과 열 자동 인식
→ 필요한 경우 열 매핑 수정
→ 정규화 미리보기와 오류/중복 확인
→ 결제수단·카테고리 지정 및 행 수정
→ 포함할 행 선택
→ 최종 확인
→ 원장 일괄 반영과 결과 요약
```

모바일에서도 사용할 수 있지만 대량 검토는 PC 화면을 우선 최적화한다.

## 5. 기능 요구사항

| ID    | 요구사항                                                         |
| ----- | ---------------------------------------------------------------- |
| FR-01 | 사용자는 접근 가능한 장부에 CSV/XLSX 명세를 업로드할 수 있다.    |
| FR-02 | 허용 확장자, 실제 파일 signature, 크기와 행 수를 검증한다.       |
| FR-03 | 자동 열 매핑이 불완전하면 사용자가 직접 매핑한다.                |
| FR-04 | 날짜·금액·수입/지출을 원장 형식으로 정규화한다.                  |
| FR-05 | 오류 행은 이유와 원본 행 번호를 표시하고 확정 대상에서 제외한다. |
| FR-06 | 기존 transaction과 중복 가능성이 있는 행을 명시한다.             |
| FR-07 | 사용자는 행별 포함 여부와 거래 정보를 수정한다.                  |
| FR-08 | 확정 작업은 선택된 모든 행을 성공시키거나 전체를 롤백한다.       |
| FR-09 | 재시도 시 동일 batch와 거래가 중복 생성되지 않는다.              |
| FR-10 | 가족 장부는 활성 구성원, 개인 장부는 소유자만 import할 수 있다.  |
| FR-11 | 반영된 거래는 `source=import`와 batch/원본 행 관계를 가진다.     |
| FR-12 | 원본 파일 내용과 금융 개인정보를 로그에 남기지 않는다.           |

## 6. 비기능 요구사항

- 10,000행 파일의 파싱 진행 상태와 취소 기능 제공
- 대량 파싱 중 메인 UI가 멈추지 않도록 Web Worker 사용 검토
- 금액 계산에 JavaScript 부동소수점 사용 금지
- 원본 파일을 Supabase Storage에 기본 업로드하지 않음
- 미리보기 데이터는 새로고침 또는 완료 후 폐기
- import batch와 transaction insert에 RLS 및 DB 검증 적용
- 모바일 주요 터치 영역 44px 이상
- 실제 금융 내역을 fixture로 커밋하지 않고 합성 데이터만 사용

## 7. 초기 데이터 모델 후보

### `ledger_import_batches`

- `id`, `household_id`, `book_id`, `account_id`, `created_by`
- 파일명에서 경로를 제거한 표시 이름, 파일 fingerprint
- 전체/정상/오류/중복/반영 행 수
- `draft`, `ready`, `committed`, `failed` 상태
- 생성·확정 시각

### `ledger_import_rows`

- batch, 원본 행 번호, 정규화 거래 fingerprint
- 정규화 일자·유형·금액·거래처·메모·카테고리
- 파싱/중복/포함 상태와 오류 코드
- 생성된 `ledger_transaction_id`

원본 전체 행 JSON 저장 여부는 개인정보 최소화 원칙에 따라 Design 단계에서 결정한다.

## 8. 성공 기준

- [ ] 합성 CSV와 XLSX를 같은 정규화 결과로 파싱한다.
- [ ] CP949 한글 CSV의 거래처가 깨지지 않는다.
- [ ] 출금/입금 분리형과 부호 금액형을 모두 처리한다.
- [ ] 잘못된 날짜·소수/음수/빈 금액을 안전하게 오류 처리한다.
- [ ] 같은 파일 재업로드와 기존 거래 중복 후보를 표시한다.
- [ ] 1,000행 import의 선택 행이 정확히 한 번만 생성된다.
- [ ] 다른 가족과 다른 사용자의 개인 장부에는 접근할 수 없다.
- [ ] 오류 발생 시 일부 거래만 저장되지 않는다.
- [ ] PC와 390px 모바일에서 핵심 흐름을 완료한다.
- [ ] lint, TypeScript, 단위 테스트, RLS 테스트와 production build가 통과한다.

## 9. 위험과 대응

| 위험                   | 영향 | 대응                                       |
| ---------------------- | ---- | ------------------------------------------ |
| 은행별 파일 형식 차이  | 높음 | 공통 정규화 모델과 adapter/preset 분리     |
| Excel 수식·악성 콘텐츠 | 높음 | 값만 읽고 수식 실행·외부 링크 추적 금지    |
| 한글 인코딩 깨짐       | 중간 | encoding 후보 감지와 사용자 재선택         |
| 중복 거래 오탐         | 높음 | 자동 삭제 금지, 후보 표시 후 사용자 확정   |
| 대량 행 브라우저 정지  | 중간 | chunk 파싱과 Web Worker 검토               |
| 금융정보 노출          | 높음 | 로컬 파싱 우선, 원본 미보관, 로그 마스킹   |
| 부분 저장              | 높음 | SECURITY DEFINER RPC와 DB transaction 사용 |

## 10. 구현 순서

1. parser input/normalized/error 타입과 합성 fixture
2. CSV 인코딩·delimiter·header 처리
3. XLSX sheet/value 처리
4. 열 자동 인식과 수동 매핑
5. import batch/row schema, trigger, RLS와 commit RPC
6. 업로드 wizard와 대량 검토 표
7. 중복 탐지와 원장 반영
8. PC/모바일·보안·성능 검증

## 11. 후속 기능

- `statement-classification`: 규칙 기반 자동 카테고리 분류
- `ledger-budget`: 월 예산과 반복 지출
- `ledger-dashboard`: 월별·카테고리별 분석
- `ledger-insights`: 설명 가능한 비용 절감 제안
