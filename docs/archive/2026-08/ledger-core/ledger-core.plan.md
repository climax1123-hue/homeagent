# ledger-core - Plan Document

> Version: 1.1.0 | Date: 2026-08-27 | Status: Approved
> Level: Dynamic

---

## 1. Overview

### 1.1 Purpose

가족 구성원이 각자 계정으로 접속해 하나의 가족 가계부를 함께 기록하고, 현금·계좌·카드별 거래와 잔액을 PC와 모바일에서 일관되게 관리할 수 있는 기준 원장을 만든다.

### 1.2 Background and Reference Findings

- 편한가계부의 빠른 입력, 수입·지출 합계, 계좌별 통계, 반복 거래, 검색, 계좌 간 이체 구조를 참고한다.
- 위플 가계부의 한 화면 빠른 입력과 월간 달력·목록 중심 탐색 방식을 참고한다.
- Spendee의 shared wallet 및 `누가 무엇을 결제했는지` 구분 방식을 가족 공동 원장에 반영한다.
- YNAB Together처럼 비밀번호를 공유하지 않고 각자 로그인하며, 공동 장부와 개인 장부의 접근 범위를 분리한다.
- Goodbudget의 계좌 선택 → 거래 등록 → 검토 흐름과 추후 파일 가져오기 시 기존 거래 매칭·중복 방지 방식을 확장 전제로 삼는다.

## 2. Goals

### 2.1 Primary Goals

- [ ] 수입·지출·이체 거래를 등록, 조회, 수정, 삭제한다.
- [ ] 현금·은행 계좌·체크카드·신용카드·기타 자산을 결제수단으로 관리한다.
- [ ] 가족 공동 장부와 개인 장부를 명확히 구분한다.
- [ ] 각 거래의 작성자와 실제 결제자를 구분해 표시한다.
- [ ] 기본 및 사용자 정의 카테고리를 제공한다.
- [ ] 월별 수입·지출·순수지와 계좌별 잔액을 즉시 확인한다.
- [ ] PC와 모바일에서 금액 입력과 최근 거래 확인을 빠르게 수행한다.
- [ ] 월·주 달력에서 일자별 수입·지출 합계와 상세 거래를 확인한다.
- [ ] 거래는 시간 입력 없이 Asia/Seoul 기준 일자로 등록한다.
- [ ] 카드 할부 원금을 월별 회차 거래로 원자적으로 생성한다.
- [ ] 관리자는 독립된 공통코드 관리 화면에서 결제수단·일정 등 시스템 전반의 코드값을 확인하고, 확장 가능한 그룹을 관리한다.
- [ ] 향후 은행 명세 가져오기, 자동 분류, 예산 및 분석 기능이 같은 원장을 사용하게 한다.

### 2.2 Non-Goals

- 은행 Open API 또는 금융기관 실시간 연결
- CSV·Excel·OFX 명세 업로드와 자동 컬럼 인식 (`statement-import`에서 구현)
- 자동 카테고리 추천과 AI 분류 (`statement-classification`에서 구현)
- 카테고리별 예산 및 월간 비용 제안 (`ledger-budget`, `ledger-insights`에서 구현)
- 영수증 사진 첨부, OCR, 대용량 파일 보관
- 복식부기 회계보고서와 세무 신고 기능

## 3. Scope

### 3.1 In Scope

#### 장부와 접근 범위

- 가족 공동 장부: 활성 가족 구성원이 조회·작성하고, 거래 작성자 또는 관리자가 수정·삭제
- 개인 장부: 소유자만 조회·작성·수정·삭제하며 관리자에게도 노출하지 않음
- 모든 데이터에 `household_id` 적용 및 RLS 강제
- 거래에 `created_by`, `payer_user_id`, `updated_by` 기록

#### 결제수단 및 자산

- 유형: 현금, 은행 계좌, 체크카드, 신용카드, 기타
- 이름, 표시 순서, 시작 잔액, 사용 여부, 공개범위
- 계좌 간 이체는 출금·입금 결제수단을 모두 지정하고 가계 수입·지출 합계에서는 제외
- 사용 중단된 결제수단은 과거 거래를 보존한 채 숨김 처리

#### 카테고리

- 거래 유형별 수입·지출 기본 카테고리
- 가족 사용자 정의 카테고리 추가·수정·정렬·비활성화
- MVP는 대분류 1단계로 시작하되 향후 소분류 확장이 가능한 구조
- 거래가 존재하는 카테고리는 삭제 대신 비활성화

#### 거래 원장

- 유형: 수입, 지출, 이체
- 필수값: 발생 시각, 금액, 결제수단, 거래 유형
- 선택값: 카테고리, 거래처/내용, 메모, 실제 결제자
- 금액은 KRW 최소 화폐 단위의 정수로 저장하고 JavaScript 부동소수점 계산 금지
- 동일 브라우저 중복 제출 방지용 client request id 지원
- 향후 import source, 원본 행 fingerprint, 분류 확신도를 연결할 수 있는 확장 지점 확보

#### 조회와 UI

- 상단 월 선택 및 이전/다음 달 이동
- 월간 요약: 수입, 지출, 순수지
- 최근 거래 목록과 날짜별 그룹
- 거래 유형·결제수단·카테고리·작성자 필터와 검색
- 빠른 거래 등록 bottom sheet/modal
- 모바일 주요 터치 영역 최소 44px
- 금액, 날짜, 거래처를 우선 보여주고 상세 정보는 점진적으로 노출

### 3.2 Out of Scope

- 할부를 제외한 자동 결제와 일반 반복 거래 생성
- 카드 결제일 및 미결제 금액 계산
- 다중 통화와 환율 변환
- 자산 평가액과 투자 수익률
- 공동 비용 정산 및 송금

## 4. Functional Requirements

| ID    | Requirement                                                                                            |
| ----- | ------------------------------------------------------------------------------------------------------ |
| FR-01 | 활성 가족 구성원은 가족 공동 장부를 조회하고 거래를 등록할 수 있다.                                    |
| FR-02 | 개인 장부 및 개인 결제수단은 소유자만 접근할 수 있다.                                                  |
| FR-03 | 수입·지출은 하나의 결제수단과 선택 카테고리를 가진다.                                                  |
| FR-04 | 이체는 출발·도착 결제수단을 가지며 두 결제수단은 달라야 한다.                                          |
| FR-05 | 모든 금액은 0보다 큰 정수이고 합계 계산은 정수 연산을 사용한다.                                        |
| FR-06 | 사용자는 월별 거래를 검색·필터링하고 합계를 확인할 수 있다.                                            |
| FR-07 | 공동 거래에는 작성자와 실제 결제자를 표시한다.                                                         |
| FR-08 | 거래 작성자 또는 가족 관리자는 공동 거래를 수정·삭제할 수 있다.                                        |
| FR-09 | 개인 거래는 가족 관리자도 조회·수정할 수 없다.                                                         |
| FR-10 | 카테고리와 결제수단 비활성화가 기존 거래를 손상시키지 않는다.                                          |
| FR-11 | 사용자 인터페이스는 낙관적 중복 저장을 방지하고 저장 실패를 명시한다.                                  |
| FR-12 | 거래 생성·수정 시각은 UTC로 저장하고 Asia/Seoul로 표시한다.                                            |
| FR-13 | 월·주 달력은 각 일자의 수입·지출 합계를 표시하고 날짜 선택 시 거래 상세를 표시한다.                    |
| FR-14 | 사용자는 거래 시간을 입력하지 않고 일자만 입력하며 DB에는 해당 일자 00:00 Asia/Seoul을 UTC로 저장한다. |
| FR-15 | 지출 할부는 총액과 개월 수를 받아 각 회차 금액의 합이 원금과 정확히 같도록 월별 거래를 생성한다.       |
| FR-16 | 관리자만 가족 공간의 확장형 공통코드를 추가·수정·비활성화할 수 있다.                                   |
| FR-17 | 계산·권한 규칙을 결정하는 값도 중앙 공통코드로 조회하되 시스템 보호 코드로 잠근다.                     |

## 5. Non-Functional Requirements

- 공개 업무 테이블 전체에 RLS 적용
- 다른 `household_id` 데이터 접근을 DB 수준에서 차단
- 개인 장부의 관리자 우회 접근 금지
- 금액 컬럼은 `bigint`, 프런트엔드는 정수 문자열 기반 입출력 사용
- 월별 10,000건의 거래에서도 날짜·장부·결제수단 필터가 인덱스를 사용
- 거래 등록은 모바일 기준 3단계 이내 진입, 주요 입력과 버튼은 44px 이상
- 실제 금융 명세, 계좌번호, 카드번호를 테스트 fixture 또는 로그에 저장하지 않음
- 거래 변경 이력의 주체를 추적할 수 있도록 작성자·수정자 필드 유지

## 6. Success Criteria

- [ ] 가족 구성원 두 명이 각각 로그인해 동일한 공동 거래 목록을 확인한다.
- [ ] 누가 작성하고 결제했는지 거래 목록과 상세에서 구분된다.
- [ ] 개인 장부의 거래가 다른 구성원과 관리자에게 노출되지 않는다.
- [ ] 수입·지출·이체 CRUD와 월별 합계가 정확하다.
- [ ] 이체 금액이 월간 수입·지출 합계에 포함되지 않는다.
- [ ] 결제수단별 계산 잔액이 거래 합계와 일치한다.
- [ ] 중복 제출, 음수·소수 금액, 동일 계좌 이체가 거부된다.
- [ ] PC 및 390px 모바일 화면에서 주요 흐름을 완료할 수 있다.
- [ ] 120만원 3개월 할부 등록 시 40만원씩 세 달에 표시된다.
- [ ] 말일 할부는 다음 달 마지막 유효 일자로 보정된다.
- [ ] 관리자가 추가한 결제수단 유형이 설정 화면에 즉시 나타난다.
- [ ] 단위 테스트, RLS pgTAP 테스트, 프로덕션 빌드와 `pnpm check`가 통과한다.

## 8. Risks and Mitigations

| Risk                             | Impact | Probability | Mitigation                                                   |
| -------------------------------- | :----: | :---------: | ------------------------------------------------------------ |
| 공동 거래와 개인 거래 권한 혼동  |  High  |   Medium    | 장부 공개범위를 상위 엔티티로 두고 모든 하위 RLS가 이를 참조 |
| 잔액 불일치                      |  High  |   Medium    | 시작 잔액 + 확정 거래 합계로 계산하고 이체 원자성 보장       |
| 금액 정밀도 오류                 |  High  |     Low     | DB `bigint`, 클라이언트 정수 문자열, 공용 합계 유틸 사용     |
| 중복 등록                        | Medium |   Medium    | 사용자별 client request id unique 제약                       |
| 명세 가져오기와 수기 거래 중복   |  High  |   Medium    | 후속 import에 fingerprint와 후보 매칭 검토 단계 포함         |
| 카테고리 변경으로 과거 통계 왜곡 | Medium |   Medium    | 삭제 대신 비활성화하고 거래의 category FK 보존               |
| 모바일 입력 피로                 | Medium |   Medium    | 금액 우선 빠른 입력, 최근 선택 기본값, 점진적 상세 입력      |
